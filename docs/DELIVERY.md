# 视频处理工具交付指南

## 一、概述

1. 本指南用于规范乙方向甲方交付视频处理工具的方式，列明交付内容、目录结构、命名、大小、文件格式和验收方法的各项关键要求。
2. **工具功能**：对成批的视频做以下处理，原视频不被修改，处理结果写到单独的输出目录。
   1. **擦除硬字幕**：自动找出画面中的字幕位置，只擦除字幕的笔画和阴影，其余画面保持原样；支持单行字幕和中英双行字幕；片中的招牌、标题书法等场景文字不会被当成字幕擦除。
   2. **擦除台标**：自动检测画面角落的静态台标，在每一帧中擦除。
   3. **提取字幕**：把识别出的字幕合并成句子级 SRT 文件，时间按帧对齐；也可以只提取字幕而不擦除。
   4. **剪除指定片段**：按给定的时间段精确到帧地剪掉片中的内容（例如插播的广告页），音频同步剪除，字幕时间同步调整；也可以自动找出画面带黑边的广告页。
   5. **批量处理**：用一份清单为每个视频单独设置选项，已完成的视频自动跳过，某个视频出错不影响其他视频。
   6. **运行前检查**：处理前先检查每个视频的字幕类型、台标位置和完整度、黑边、时间戳和音频是否有问题，并生成推荐的批量清单。
   7. **多进程加速**：长视频自动切段并行处理，再合并为一个文件；原音频流不重新编码。
3. 本指南中的「甲方」指工具接收方，「乙方」指工具提供方，与双方所签协议中的称谓一致。本指南与协议正文不一致的，以协议正文为准。
4. **本次交付的是工具（源代码、安装脚本和使用说明 README.md，即 release 版本），不是数据，也不是视频。** 乙方不交付任何视频或字幕；工具运行所需的 ProPainter 代码和 3 个权重文件随工具一并提供（附其 LICENSE）；甲方的视频由甲方在自己的环境中用本工具处理，处理结果也留在甲方环境中。
5. 实际执行中，部分要求可能需要灵活处理（例如甲方的服务器无法访问外网）。乙方将与甲方对接人协商，确定最适合具体情况的方案。
6. 在试用评估阶段，遵守本指南有助于后续工作，但不作硬性要求；评估交付的内容必须附 README.md 加以说明。

## 二、流程概览

1. 【乙方】建立交付通道。通常为本地存储，或者由乙方在甲方指定的服务器上部署。
2. 【乙方】阅读并遵守本指南的各项要求，整理交付目录。
3. 【乙方】把交付目录交给甲方，并说明工具版本。
4. 【甲方】按 README.md 安装，并按第九条的方法自检。
5. 【甲方】用自有视频试跑，审阅处理结果，把问题反馈给乙方。
6. 【乙方】根据甲方的反馈修改，并交付新版本。
7. 【甲方】确认后，把工具部署到自己的生产环境。

## 三、建立交付通道

乙方把交付包（一个压缩包，解压后是一个文件夹）直接交给甲方，或上传到甲方指定的服务器（见第七条）。

乙方在甲方指定的服务器上部署时，乙方保证部署目录中只有工具本身，不含甲方的视频以外的任何数据；处理结果（`*_clean.mp4`、`*.srt`）由甲方自行验收和复制。

乙方应遵守以下五方面的要求：

1. 目录结构
2. 文件命名
3. 限制
4. 文件格式
5. 验收与自检

## 五、目录结构

### 示例

```
tool_delivery（乙方共享目录）
  video_tool_0.3.4（版本号放在目录名中）
    README.md（安装、使用、依赖、许可说明）
    pyproject.toml（依赖声明和版本）
    .agents
      skills
        video-tool
          SKILL.md（Codex 操作助手，见下）
    scripts
      install.sh（Linux 安装脚本）
      install.bat（Windows 安装脚本）
    ProPainter（第三方视频修复模型：官方代码和 3 个权重文件，附 LICENSE）
      LICENSE
      weights（3 个 .pth 权重文件）
      model、RAFT、core、utils（模型代码）
    src
      clean_clear
        cli.py、pipeline.py ……（源代码）
        backends
          lama.py、propainter.py
```

### 各目录说明

1. **README.md**（模板见附录一）应写明：
   1. 工具的总体信息：名称、版本、功能、适用范围、使用限制（见第 2 款）。
   2. 运行环境：操作系统、Python 版本、GPU 和驱动要求、ffmpeg。
   3. 安装方法和依赖来源，包括需要另行下载的模型及其下载地址。
   4. 基本用法、常用选项，以及输入、输出文件说明（见第八条）。
   5. 自检方法（见第九条）。
2. **许可与使用限制**：README.md 必须列出工具使用的第三方组件及其许可证。其中 ProPainter 模型（视频修复，默认的最高质量模式）采用 NTU S-Lab License 1.0，**仅限非商业用途**；LaMa 模型采用 Apache-2.0。甲方的使用场景若属商业用途，应使用 `--model lama`，或另行取得 ProPainter 的授权。
3. **scripts**：只放安装脚本。脚本不得包含密码、密钥、账号。
4. **src**：工具的源代码。
   **.agents/skills/video-tool/SKILL.md**：给甲方的 Codex 用的操作助手（Skill），告诉 Codex 如何安装、检查、批量运行和验收。在这个交付目录里启动 Codex 会自动识别；也可以复制到 `~/.agents/skills/` 下全局使用。
5. **只交付 release 版本**：即 README.md、`pyproject.toml`、`scripts`、`src`、`ProPainter`（代码、权重和 LICENSE），以及可选的 `.agents/skills/video-tool/SKILL.md`。自动化测试（`tests/`）和开发文档（`docs/`）不随交付包提供。
6. **不得放入交付目录的内容**：
   1. 任何视频、字幕或处理结果，包括甲方的视频和乙方的测试视频。
   2. ffmpeg 等系统程序，以及 LaMa 和 OCR 模型文件（`models/`、`ffmpeg/`）。它们由甲方的环境提供，或在首次运行时自动下载。
   3. 虚拟环境（`.venv/`）、缓存（`.cache/`）、日志、`__pycache__/`、`*.egg-info/`。
   4. 乙方的开发笔记、其他客户的资料、任何账号或密钥。
7. 不得在目录名或文件名中写入与客户或影片有关的信息，例如片名、客户名。

## 六、文件命名

### 必须

1. 交付包内的所有目录名和文件名须符合正则表达式 `[0-9a-zA-Z._-]+`，不得含空格、中文或其他特殊字符。

### 建议

1. 文件名简洁、易于识别。
2. 使用标准扩展名表示文件格式，例如 `.py`、`.md`、`.sh`、`.bat`、`.toml`。

> 说明：以上要求只针对交付包本身。工具处理的视频的文件名不受限制，可以含中文和空格，工具按「原文件名 + 后缀」生成输出文件（见附录二）。

## 七、限制

### 交付包的限制

1. 交付包以一个压缩包（`.tar.gz`）提供，方便上传到服务器；解压后是一个文件夹。包内不得再嵌套压缩包。
2. 压缩包约 185 MB：其中 ProPainter 的 3 个权重文件约 200 MB（未压缩），工具的源代码约 0.2 MB（约 3600 行）。没有其他大小要求。
3. LaMa 模型（约 200 MB，仅 `--model lama` 时需要）和 OCR 模型（约 30 MB）不在交付包内，首次运行时自动下载。

### 工具的使用限制

1. **运行环境**：需要 NVIDIA GPU（4 GB 以上显存）。没有 GPU 也能运行，但很慢。用 ProPainter 时每个处理进程约占 6.5 GB 显存（720p 视频），1080p 视频的字幕区域最多约 13 GB；多进程并行时显存按进程数相加，显存不足时程序会给出警告。
2. **许可**：ProPainter 仅限非商业用途，商业用途请使用 LaMa（画质低一档，速度快 5–7 倍）。
3. **处理对象**：只处理画面里烧录的硬字幕和固定在角落的静态台标；字幕默认在画面下方，在上方时用 `--band` 指定。
4. **字幕颜色**：按白色字幕优化；其他颜色会退回到整块文字框擦除，填补处会略模糊。
5. **字幕识别**：识别准确率不保证，提取的 SRT 需要人工校对。
6. **台标检测**：偏暗的片子里，半透明台标可能只检测到一部分。运行前用 `--probe` 检查，有警告时改用已知的台标掩码（`--watermark`、`--logo-library`）。
7. **场景文字**：字幕行上的场景文字（例如字幕后面屏幕上的品牌名）可能随字幕一起被擦掉；台标压在细节丰富的背景上时，填补处可能糊掉一部分背景。
8. **音频空洞**：音频时间线上有空洞的源文件，处理后空洞（静音）原样保留，不要对这类音频做变速处理。
9. **广告页**：只能在带黑边的片子里、并且画面中有网址时自动找出；其他情况用 `--cut` 按时间段剪除。
10. **版权**：擦除第三方台标或字幕，可能侵犯内容权利人的权益。工具不检查版权归属，由使用者负责。

## 八、文件格式

### （一）源代码与脚本

1. Python 3.10 及以上，所有文本文件使用 UTF-8 编码。
2. Linux 脚本（`.sh`）使用 LF 换行，Windows 脚本（`.bat`）使用 CRLF 换行。
3. 命令行入口：`clean-clear`（安装后由 `pyproject.toml` 提供），也可用 `python -m clean_clear`。

### （二）使用说明

1. README.md 使用 Markdown（UTF-8）。
2. 命令、路径、选项名写在代码块或行内代码中，方便复制。

### （三）依赖声明与安装

1. 依赖统一写在 `pyproject.toml` 中，由 pip 从 PyPI 安装；在中国大陆使用本地镜像（腾讯云、华为云等），镜像地址写在 README.md 中。
2. 可选依赖：`propainter`（PyTorch 等，选用 ProPainter 时安装）。
3. 需要 ffmpeg 和 ffprobe，由甲方自行安装。

### （四）工具的输入和输出格式

**输入**：视频文件或目录，扩展名 mp4、mkv、mov、avi、flv、ts、m4v、wmv、webm。

**输出**：写到 `-o` 指定的输出目录（默认为当前目录），不修改原视频。

| 文件 | 格式 | 说明 |
|---|---|---|
| `NAME_clean.mp4` | H.264 视频 + 原音频流（不重新编码），分辨率和帧率与原片一致 | 擦除字幕和台标后的视频 |
| `NAME.srt` | SRT，UTF-8 | 识别出的字幕，句子级，时间按帧对齐；无字幕的片子不生成 |
| `clean-clear.log` | 文本，UTF-8 | 所有运行的日志，带时间戳 |
| `batch-status.txt` | 制表符分隔文本：文件名、状态、用时 | 批量运行结束时的汇总 |
| `NAME.probe.json`、`probe-batch.txt` | JSON、文本 | 仅 `--probe` 时生成，见附录二 |
| `.cache/` | 内部缓存 | 可删除，删除后只是重新识别 |

输出文件是甲方视频的处理结果，不属于乙方的交付内容，不适用「数据交付」的各项要求。`NAME.probe.json` 是给人看的检查记录，也不是数据交付文件。

### （五）运行时的网络访问

1. 工具本身不上传视频、字幕或识别结果，全部在本机处理。
2. 仅在首次运行时联网下载模型（LaMa：Hugging Face 或其国内镜像；OCR 模型：ModelScope）。离线环境可由乙方协助预置，方法见 README.md。
3. 工具不含个人身份信息，也不收集儿童相关数据。甲方视频中如含此类内容，由甲方负责。

## 九、验收与自检

甲方安装完成后，按以下顺序自检；每一步都不需要乙方的视频。

| 步骤 | 命令 | 通过的标志 |
|---|---|---|
| 1. 命令可用 | `clean-clear --help` | 打印选项列表 |
| 2. GPU 可用 | 安装脚本末尾的输出，或 `python -c "import onnxruntime as o; o.preload_dlls(); print(o.get_available_providers())"` | 含 `CUDAExecutionProvider` |
| 3. 检查自己的视频 | `clean-clear --probe 视频目录 -o 检查目录` | 生成 `probe-batch.txt`，其中的 `WARN` 注释已逐条确认 |
| 4. 试跑 | 先用一段 5 分钟的片段运行，检查字幕和台标是否擦干净、音画是否同步 | 与原片对照无残留、无明显闪动 |
| 5. 批量运行 | `clean-clear --list 检查目录/probe-batch.txt -o 输出目录` | `batch-status.txt` 中全部为 `ok` |

乙方在每次交付新版本时，同时说明本版本相对上一版本的变更和已知限制。

## 附录二 批量清单与检查文件

### 批量清单（`--list`）

一行一个视频：路径加上该视频自己的选项。以 `#` 开头的行是注释；以 `DEFAULT` 开头的行为它下面的所有视频设置选项。

```
# 示例
DEFAULT --crf 18

"/data/videos/film one.mp4"
"/data/videos/film two.mp4"  --subtitles off
"/data/videos/film three.mp4" --band 0,0.3
```

1. 路径含空格时用引号括起来。
2. 视频一个接一个处理；某个视频失败不影响其他视频。
3. 输出目录中已存在 `NAME_clean.mp4` 的视频会被跳过，所以中断后可以用同一个清单继续。
4. 运行结束后写出 `batch-status.txt`。

### 运行前检查（`--probe`）

`clean-clear --probe 视频目录 -o 检查目录` 不擦除任何内容，每部片子约 1 分钟，检查：

1. 有没有硬字幕、是单行还是中英双行、在画面上方还是下方。
2. 台标在画面的哪个角，检测到的台标范围是否完整（偏暗的片子容易检不全）。
3. 有没有黑边。
4. 视频时间戳是否规则、音频有没有空洞。

输出 `NAME.probe.json`（检查记录）和 `probe-batch.txt`（带推荐选项的批量清单，拿不准的地方写成 `# WARN` 注释，需要人工确认）。
